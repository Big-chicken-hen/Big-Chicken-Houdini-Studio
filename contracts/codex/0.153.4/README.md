# Native integration contract

`integration.json` is a field-level excerpt from schemas generated by the installed `codex-cli 0.153.4` using `codex app-server generate-json-schema`. It retains only requests consumed by Studio, native turn/thread status definitions and the advertised reasoning-effort type. Each entry under `requests` is its own schema fragment; resolve its `#/definitions` references within that entry. The envelope is a catalog, not one JSON Schema for an entire RPC exchange.

The allowed method surface is in `src/studio/codex/protocol.py`. `env_vars` forwards variable names to the MCP child; session credentials never become literal thread configuration. Scene threads disable repository instruction scanning and use Studio's scene instructions. Thread and turn history remain native Codex data.

Native checks on Windows with 0.153.4 confirmed initialization, `model/list`, an empty isolated `account/read`, and `thread/start` with the actual Studio MCP configuration. The model response advertises effort strings through `ultra`; the UI consumes those strings without replacing them with a fixed legacy enum. No inference or login was performed.

An idle thread before its first turn has no rollout to resume. In this build, `thread/read` with `includeTurns: true` returns `list_turns is not supported yet`; metadata-only reads work. Bridge narrowly handles that response as unavailable native history and preserves the native status. It does not invent a persistent history, automatically replay a turn or turn a failed response into a successful Houdini receipt.

After `turn/interrupt` acknowledges the request, native terminal events or an explicit native state query determine the Codex state. Runtime receipts independently determine HOM state. See the official [App Server documentation](https://learn.chatgpt.com/docs/app-server) for the lifecycle and protocol overview; generated fields and actual installed-version checks govern this release.

Saved multi-turn history, authenticated inference, approvals during inference, native MCP image delivery through a real model turn, and effective context capacity still require a real session. Unit event fixtures and an empty native thread do not verify those flows.
