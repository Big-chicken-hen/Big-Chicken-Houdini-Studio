## 已实施的小范围修正

1. `_HttpJob` 在调用 `HTTPConnection.request()` **之前**标记请求可能写出。
   socket 创建、连接或连接后取消发生在该标记前，才可归为 `not_submitted`。
   请求可能部分写出、响应头丢失、响应截断等仍为 `unknown`，不自动重发。
   `status is None` 不作为未发送证据。
2. 消息 POST 的终态按原 Api、原消息快照、native connection/account 身份
   处理，不再因一个后台读取推进 UI 连接代次而被丢弃。普通历史/事件回调
   仍使用原来的代次隔离。账号或 native connection 改变、Api 替换、Panel
   关闭及已删除对话不能借此接受旧结果。
3. 明确未发送时解除当前提交的不确定状态，恢复空输入区；已有新草稿或
   IME 组合输入时保留原快照供原有入口查看，不覆盖新草稿。不自动再次发送。
   内存草稿/快照不被描述成跨重启持久化。
4. `/state` 失败后，基础轮询按 1.7、3.4、6.8、13.6、20 秒退避，20 秒封顶。
   在故障模式中只保留去重的 `/state` 探测，暂停常规账号和历史读取；显式
   刷新连接可立即尝试一次。有效状态恢复后恢复原 850 毫秒间隔，合并读取
   events/account/history。没有给 turn/steer 增加自动重试队列。
5. 传输错误详情带时间、PID、Api/请求身份、归一化路由、本机目标端点、
   阶段、异常类型和 errno/winerror。关联消息只用摘要；堆栈仅保留函数、
   行号和 Studio 内的相对文件名，外部文件路径替换为 `<external>`。
   不记录请求正文、认证头、图片/附件内容、环境变量或历史。

仍使用现有 Python HTTP IO、独立 Stop HTTP 线程和标准库解析器，未启用
连接池、HTTP/1.1、Qt Network 回退、全局 TCP 设置或代理更改。

## 默认关闭的限时诊断

`http_diagnostics.py` 提供 Panel 本地取证。没有启用标记时不会建立日志文件。
启用仅对该缓存根中新建的 Panel Api 生效：

- 标记：`<BCS_CACHE_ROOT>/diagnostics/http-trace.enabled`。
- 有效期：从标记的修改时间起 15 分钟；过期标记不会在以后启动时重新启用。
- 输出：同目录 `panel-http-<PID>.jsonl` 及一个轮换文件。
- 容量：每个进程/缓存根至多两个 256 KiB 文件；不同进程的文件分别保留。
- 异常即时记录安全字段；每 30 秒在请求结束时输出路由级请求、完成、失败、
  取消、在途和峰值计数。计数包含排队等待的 HTTP 工作请求，不等于 TCP
  socket 数量或 TIME_WAIT 数量；它只覆盖 Panel → Bridge，不涵盖整台系统。
- 开头记录采集版本及模块位置。磁盘路径本身不是已加载字节的证明；后续
  验收还应记录候选提交和实际启动入口。
- 未启用任何真实用户会话的采集。本轮仅在隔离测试目录验证该机制。
- 原有诊断 ZIP 白名单没有扩大，本地 trace 不会被自动打包或上传。

取证前先保存未确认原文、正在编辑的新草稿和附件引用，避免通过关闭 Panel
或 Houdini 丢掉尚未到达 Bridge 的内存内容。采集可在下一次正常新开会话前
准备；不需要为获取路径反复打断当前场景。
