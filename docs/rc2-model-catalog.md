# RC2 模型目录同步

2026-11-18 在同一 Studio ChatGPT 账号和项目网络配置下，对比了官方 Windows x64 Codex
0.153.4 与 0.170.0 的原生 `model/list`。两次读取都确认账号已登录，且原生缓存的
`client_version` 和刷新时间与运行中的二进制一致。验证使用既有认证的原生读取和独立
日志、SQLite 目录，无需登录或复制凭据。

| 二进制 | 原生可见目录 |
| --- | --- |
| 0.153.4 | 4 项。刷新后仍未返回 GPT-6.2 Sol 或 GPT-6.2 Astra。 |
| 0.170.0 | 10 项。包括 `gpt-6.2-sol`、`gpt-6.2-astra`，两者均返回 `max`。 |

分别用小页确认实际存在游标。Studio 的现有目录聚合读取完整结果，隐藏项继续由原生
列表和现有过滤处理。两个二进制各重复三次查询，返回一致。结合原生目录按客户端
版本请求的实现，旧二进制收到的目录已能解释模型缺失。[上游模型管理器](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/models-manager/src/manager.rs)

RC2 固定 Codex 0.170.0。Panel 每次打开模型选择器时重新读取同一原生目录，复用现有
账号隔离、并发保护和 Bridge 的 60 秒缓存。模型标识和档位均来自原生响应。
模型是否可见取决于当前账号和上游所提供的目录。[0.170.0 协议摘录](../contracts/codex/0.170.0/README.md)

## 兼容验证

- 实际 Windows 二进制使用项目隔离数据和本地受控 Responses 服务。0.153.4 创建并落盘的 Thread 可被 0.170.0 列出、读取和恢复，原输入身份保留。
- 同一 native Turn 有三次顺序追加，相同正文的三个客户端 ID 在原生历史中各出现一次。核对了错误 Turn、轮次结束、真实 Turn 和 Item 游标，以及 Stop 后的原生终态。受控服务收到 `gpt-6.2-sol` 和 `max`。
- 用生产 Studio MCP 配置触发的许可请求可与原生工具项精确关联，并可明确拒绝。保留现有一次性发送及未知结果查询语义。五种既有许可和输入请求的生成入口与上一版一致。
- 107 项本机定向测试通过，覆盖模型设置、严格版本检查、Qt 目录刷新、发送竞态、迟到确认和原会话恢复。Ruff 静态检查通过。

本轮没有对新候选运行真实 Houdini GUI、外部模型推理或独立标准用户安装。
[首发外测报告及公开包](rc1-public-preview.md)的范围是原候选。
