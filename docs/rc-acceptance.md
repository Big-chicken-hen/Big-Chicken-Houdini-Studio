# Windows RC 验收步骤

当前状态：内部安装包和本步骤已准备；**尚未通过干净的非管理员用户环境验收**。
NET-1 已通过 [两次实际包 Houdini 回归](r4-net-validation.md)。按 [最终审批](final-release-brief.md)，
本流程必须使用包含 native steer 的最终候选，旧包结果不能代替本次验收。
最新 [审批与用户修正](rc-trial-scope.md) 允许日常 RC 和定向同学试测。用户暂时没有标准用户测试环境，R4 保持 Draft，不公开发行。
构建结果与已完成的检查见 [R4 验证记录](r4-validation.md)。

## 验收条件

- Windows 11 x64 的普通非管理员账号；证明运行不依赖开发 checkout、PYTHONPATH 或外部 Python/Node/Git。机器可以已有正常 Houdini 和其他开发软件，不要求卸载。
- 已安装 Houdini FX 22.0.368，并有可用许可证。
- 使用测试者自己的有效 Clash 配置与官方账号，端口无需与开发机相同。不关闭 Clash 或修改全局代理做测试；外部连接被网络阻断时记 BLOCKED。其他 Houdini 22 系列可按 Untested 确认试测，但不能替代本项已验证组合的完整标准用户 gate。
- 本次实际 RC 安装器及配套 `.sha256`；记录文件名、校验值、安装时间和安装路径。
- 一份允许修改的测试 HIP 副本。后续操作只使用这份副本。

此候选未签名。如果系统阻止运行，记录提示并停止这一项；不关闭系统保护。
不从其他账号或安装目录复制认证文件。

## 执行顺序

| 步骤 | 操作 | 通过条件与保留证据 |
| --- | --- | --- |
| 1. 安装 | 选择含空格和中文的用户安装目录；安装后从开始菜单打开 Studio。 | 普通账号完成安装；没有要求安装 Python、Node、Git 或运行开发命令。记录目录和首屏。 |
| 2. 检测与登录 | 确认随包 Codex 和已有 Houdini；通过启动器完成官方登录。 | Codex 显示 0.153.4，Houdini 显示 22.0.368。缺失或不兼容时提示准确；没有偷偷启动 Houdini。 |
| 3. 连续创作 | 打开测试 HIP，进入 Panel，开启本对话场景许可。请求第一次修改、查看图片，再请求第二次修改。 | 同一对话连续工作；消息不混入其他对话，长回复完整；活动分组紧凑，图片与失败提示可见。保留原生对话和操作收据。 |
| 3a. 工作中引导 | 第一轮仍在工作时，在同一 Composer 追加一个明确要求；确认已接纳后可再次追加。 | Send 和 Stop 同时可见；至少一次引导被接纳到原 Thread/Turn，未创建另一轮；每条用户消息在原生历史中只出现一次，新草稿不被 ACK 清除。新增要求实际影响后续工作。若 Turn 已结束，保留输入并明确未发送，不能算成功 steer。 |
| 4. 保存与续作 | Save As 到明确的测试输出路径，关闭 Houdini，再从启动器重开该文件，继续原对话完成第三次修改。 | HIP 和原对话对应正确；原 native cwd、收据、附件保持可访问。另记微软拼音在正文和“项目约定”输入框中的表现。 |
| 5. Stop | 在分阶段执行过程中点击 Stop。 | 分别记录 Codex 停止请求与 Runtime 收据；允许当前 HOM 步骤结束，已发生的修改诚实保留，后续步骤不盲目重放。 |
| 6. 升级 | Studio 会话仍打开时运行另一份候选安装器；按提示正常关闭会话，再完成升级。 | 安装器不强制结束 Houdini，不覆盖使用中的版本；上一版本保留。升级后原对话、场景、收据、附件和未保存场景的临时输出仍可用。 |
| 7. 诊断 | 从启动器已有详情页选择“导出诊断”，核对确认框的位置与内容，导出新的 ZIP。 | ZIP 只包含 `diagnostics.json`；没有聊天、脚本、账号凭证、图片或 HIP/HDA，也没有自动上传。 |
| 8. 卸载与重装 | 正常关闭全部 Studio 会话，卸载程序，检查用户数据，再重新安装并打开原对话。 | 程序和快捷方式移除；用户 state、native history、收据、附件、已保存文件及 cache 下未保存的作品保留。重装后可以续作。 |

默认用户数据与缓存分别在 `%LOCALAPPDATA%\BigChickenStudio\state` 和
`%LOCALAPPDATA%\BigChickenStudio\cache`。如果当前会话使用其他明确选择的旧目录，
按它实际记录的目录核对，不移动或重新编号。Save As 不迁移 active workspace 或 native cwd。

## 结果记录

每一步记录“通过 / 失败 / 未测”、时间、必要截图，以及实际出现的 Thread / operation 标识。
失败时保留原记录和现场；结果不明先查询原请求，不重复执行脚本来补收据。
不要把认证信息、聊天正文或完整环境变量贴入公开 issue。

独立标准用户尚未执行完整流程。只有这些项目完成、发现的问题得到处理并通过复核后，
才能批准 R4 合并和公开发行。开发账号的离屏截图或源码测试不替代这一结果。
最终记录必须对应候选的 source commit、builder commit、build ID、依赖 lock 和安装器
SHA-256；通过后发布这同一份安装器，不在合并后重新打包替换。若仍没有标准用户环境，
冻结候选并保持 PR #14 Draft，不把未测项改为通过。
